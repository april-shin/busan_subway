# 요구사항 리뷰 결과 — 급행 가상 노선 모델링

## 원래 요청

> "9호선 언주→마곡나루 같은 경로에서 실제 가장 빠른 경로(언주→신논현 완행 1정거장 → 신논현에서 9호선 급행 환승 → 마곡나루)를 Dijkstra가 자동 탐색"

## 승인된 plan 핵심 결정

1. 그래프·경로 모델링만 (기존 토글 UI 유지)
2. 모드 전환 edge weight = 배차간격/2
3. 환승 대기 시간 Dijkstra 반영
4. UI 노선명 "9호선 급행"

## 기능 완전성

### 핵심 요구사항 (요청된 시나리오)

- ✅ **언주(926)→신논현(925) 완행 1정거장 자동 선택** — 그래프상 언주는 급행 미정차역(skip edge에 없음)이라 9호선 완행 노드(`926_9`)에서 출발. Dijkstra가 인접 완행 edge로 신논현까지 115초.
- ✅ **신논현(925)에서 급행 모드 전환** — `925_9 ↔ 925_9E` 사이 9M edge(weight=150초, isTransfer=true)가 빌더에서 생성됨.
- ✅ **신논현→마곡나루 급행 직통 경로 탐색** — 9E 그래프에서 `925→923→920→917→915→913→910→907→905`로 8 hop, 1805초 도달 확인 (Python BFS 시뮬레이션). 완행 단독(약 52분)보다 명확히 빠름.
- ✅ **Dijkstra 자동 선택** — 알고리즘 자체 변경 없음. 그래프 구조 확장만으로 동작.

## 엣지 케이스 검증

### 회귀 (완행 단독 경로)

- ✅ `headwaySeconds`가 비어있으면 환승 weight에 대기시간 미가산 (레거시 호환). 테스트 `headwaySeconds가 비어있으면 환승 weight는 transferTime 그대로` 통과.
- ✅ `expressSkipEdges`가 비어있으면 `_E` 노드/`_M` edge 미생성. 테스트 `expressSkipEdges가 비어있으면 가상 _E 노드/세그먼트 미생성` 통과.
- ✅ 2호선 등 급행 없는 노선은 변경 영향 없음 (graph_builder의 급행 빌드는 expressSkipEdges에 등장하는 lineId만 처리).

### 9호선 급행 그래프 분리 — ⚠ 새 발견

데이터 추출 알고리즘이 인접역(skipped=0) 쌍을 의도적으로 제외하면서, **9호선 급행 그래프가 두 컴포넌트로 분리**:
- 컴포넌트 A: 902(김포공항) ~ 929(봉은사) — 12개 노드
- 컴포넌트 B: 930(종합운동장), 933(석촌), 936(올림픽공원), 938(중앙보훈병원) — 4개 노드

원인: 봉은사(929)↔종합운동장(930)이 인접역이라 BFS skipped 길이=0 → 추출 시 필터됨. 232개 trainno에서 등장하는데도 9E 그래프에 누락.

**사용자 영향**:
- 신논현→마곡나루 (요청 시나리오): A 컴포넌트 내부라 OK. ✅
- 신논현→중앙보훈병원: B 컴포넌트 진입을 위해 봉은사(929_9E) → 봉은사(929_9) 모드 전환 → 종합운동장(930_9) 완행 → 종합운동장(930_9E) 모드 전환 우회. Dijkstra는 답을 찾지만 추가 모드 전환 비용 ~300초 발생.
- 김포공항→중앙보훈병원: 동일하게 봉은사/종합운동장에서 우회 모드 전환 필요.

**우선순위**: HIGH. implementation.md의 트레이드오프 #1에 "수인분당선 BFS 부정확"만 언급되었고 **9호선 인접역 단절은 미문서화**. 9호선이 핵심 시나리오 노선이고, 사용자가 "신논현에서 환승해서 가장 빠른 급행" 외 다른 9호선 급행 경로(예: 김포공항→중앙보훈병원)를 시도하면 비효율 경로가 나올 수 있음.

**권장 수정**: `extract_express_skip_edges.py`의 `if len(skipped_ids) == 0: continue` 필터를 제거하거나, 인접 급행 정차역 쌍은 별도로 추가하는 보완 로직 도입. 완행 edge와 weight 차이가 있으면(급행이 살짝 빠름/느림) 실제 시간 반영이 정확해짐.

### 급행 그래프 무결성 일반

- ⚠ **수인분당선/1호선도 동일 위험**: 인접 정차역 쌍이 잘렸을 수 있음. 현재 1호선 478 edge 중 인접 쌍 누락이 다른 컴포넌트 분리를 일으키는지 미확인.

### 환승역 시간 누적 표시

- ⚠ implementation.md 트레이드오프 #4 — 모드 전환을 일반 환승처럼 표시. 사용자가 "9호선→9호선 급행"을 환승으로 인식할 수 있음. UX 후속 PR 필요.

### 노선별 배차 fallback

- ✅ headway 데이터가 누락된 노선은 `_defaultHeadwaySeconds = 180` (3분) → 모드 전환 wait 90초 폴백. 합리적.

### 하행 방향

- ✅ 9E edge는 양방향(`addBidirectionalEdge`)으로 추가됨 → 마곡나루→신논현 같은 역방향도 동일하게 작동.
- ✅ 환승 edge는 비대칭 양방향(개별 addEdge 두 번)으로 도착 노선별 다른 대기시간 반영.

### 동일역 동일노선 재진입 방지

- 검토 결과 명시 처리 없음. 모드 전환 edge로 들어갔다가 곧바로 같은 역에서 나오는 0초+0초 패턴은 발생하지 않음 (모드 전환 weight ≥ 90초). OK.
