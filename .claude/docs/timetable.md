# 열차 시간표 (하이브리드: 역별 시간표 + 배차간격 폴백)

`assets/json/line_schedules.json`에 23개 노선의 양방향 운행 스케줄을 컴팩트 JSON으로 보유한다:
- 노선별 상행(내선)/하행(외선) 첫차·막차 시간
- 시간대별 배차간격 (첨두 06:30-09:00/16:30-19:30, 비첨두, 심야)
- 하행 전용 배차간격이 상행과 다를 경우 `pD` 키로 별도 저장
- 역별 정확한 출발시각 목록이 있으면 `t` 키로 저장 (배차간격 대신 사용)

## 컴팩트 JSON 스키마

```json
{
  "id": "1",
  "wd": {
    "f": ["05:20","05:18"],
    "l": ["00:48","00:42"],
    "p": [["05:00","06:00",5],["06:00","09:00",4]],
    "t": {
      "P01": [null, [330, 340, 350, 360]],
      "P05": [[335, 345, 355], [328, 338, 348]]
    }
  },
  "we": { ... }
}
```
- `id` = lineId, `wd` = 평일 (필수), `we` = 주말 (옵셔널, 없으면 `wd`와 동일)
- `f` = firstTrains [상행/내선, 하행/외선], `l` = lastTrains [상행/내선, 하행/외선]
- `p` = 공유 배차간격 [[시작,종료,배차분]], `pD` = 하행 전용 배차간격 (상이할 경우만)
- `t` = 완행 역별 시간표 (옵셔널). `stationId → [상행출발분목록, 하행출발분목록]`
  - 각 목록은 자정 기준 분(minute) 단위 정렬된 정수 배열 (예: 330 = 05:30)
  - 자정 이후 출발은 1440+ (예: 24:49 → 1489)
  - `null`은 해당 방향 출발 없음 (종착역 등)
  - `t`가 없는 역은 `p` 배차간격으로 폴백
- `tE` = 급행 역별 시간표 (옵셔널, 구조는 `t`와 동일). 급행 미정차역은 키가 없다.
  - 급행이 역을 통과하는 노선(9호선)에서 완행(`t`)과 분리 저장한다. 한 배열로 합치면
    급행 미정차역에 급행 출발시각이 섞이는 오류가 생기기 때문.
  - 급행 모드(`{base}E` 가상 노선) 라우팅 시 `findNextDeparture(express: true)`가 `tE`만 조회하며,
    해당 역 급행 데이터가 없으면 완행과 섞지 않고 배차간격으로 폴백한다.
  - 파싱: `DaySchedule.expressStationDepartures` (완행은 `stationDepartures`)
- 상하행 첫차/막차가 동일하고 `pD`/`t`/`tE` 없으면 하행 데이터는 상행으로 자동 폴백

## 역별 시간표 지원 노선

- **김포골드라인 (P01~P10)**: 구간운행(short-turn)이 있어 역별 배차간격이 다름. 10개 역 전체 평일/주말 시간표 포함.
  (수집 경로는 아래 "비서울교통공사 노선 12개" 항목과 동일 — 여기는 노선 고유 특성만 정리.)
  - 데이터 출처: **getTrainSch 단일화**(2026-07-27). 이전에는 P01~P09 가 korailinfo.com 수동 데이터,
    P10 은 미수집이었다. korailinfo 원본이 구간운행 편성을 상당수 누락해(구래 김포공항방면 127편 →
    실제 258편) 구래 출발 조회 시 실제보다 늦은 열차를 안내하던 문제가 있었다. 이관으로 평일 총
    출발이 3,773 → 4,343건이 됐다.
  - 편성 체계(평일, 수집 시 확인): **3xxx** 전구간(양촌↔김포공항) 100편, **2xxx** 구간운행
    (구래↔김포공항) 158편, **7xxx** 비영업 2편(제외 — 아래 참고).
  - 방향별 편수가 구래에서 꺾이는 것이 정상이다 — 158편이 구래에서 회차하므로:
    - 김포공항 방면: 양촌 100 → **구래 258** → 마산~고촌 258~259
    - 양촌 방면: 김포공항~마산 259 → **구래 101** → 양촌 0(종점)
  - 종점 처리: P01(양촌)은 `[null, 공항방면]`, P10(김포공항)은 `[양촌방면, null]`.
  - ⚠ `f`/`l`(첫차·막차)은 `extract_schedules` 산출값이라 역별 시간표와 어긋난다
    (평일 `l=23:30` vs 실측 막차 24:58). 역별 시간표 경로(`_nextStationDeparture`)는
    `lastTrainMinutes` 를 보지 않으므로 잘림은 없다 — `f` 는 "전날 자정 넘김 조회" 판단에만 쓰인다.
  - `tool/convert_gimpo_timetable.dart` / `build_gimpo_json.dart` 는 **레거시**(korailinfo 경로). 더 이상
    실행하지 말 것 — 실행하면 P01~P09 가 구간운행 누락 데이터로 되돌아간다.
- **경의중앙선 (K01~K56)**: 급행/완행 혼합 운행으로 역별 정차 패턴이 다름. 56개 역 전체 평일/주말 시간표 포함.
  - 경의중앙선(용문↔문산) + 경의선(서울↔문산) 열차를 역별로 통합
  - K54(서울역)는 K24(효창공원앞)에서 분기하는 지선, 경의선 열차만 정차
  - K55(임진강), K56(운천)은 K01(문산) 이북 연장 구간, 하루 2~4편 운행
  - 데이터 출처: 코레일 시간표 엑셀 (`assets/excel/center_line260228.xlsx`)
- **서울교통공사 운영 노선 1~9호선**: 서울 열린데이터광장 API에서 역별 시간표 수집.
  - **1호선**: 100역 완행(`t`) + 급행 94역(`tE`). 1호선 급행은 급행분류(EXPRESS_YN=D) 열차 기준이며
    경원선/도심 구간에선 각 역 정차하므로 tE가 광범위. 완행모드는 `t`(G), 급행모드는 `tE`(D)로 분리.
    (`express_skip_edges.json`에 `1` 존재 → `1E` 라우팅 활성)
  - **3(44)·4(51)·5(56)·6(39)·7(53)·8(24)호선**: 전 역 완행(`t`)만. 급행 없음(`tE` 없음).
  - **2호선(순환, 51역)**: 2026-07 데이터셋 갱신으로 신규 제공 시작 → 전 역 수집 완료. 완행(`t`)만.
    순환선도 방향 매핑은 동일(`INOUT_TAG` 1=상행/내선→idx0, 2=하행/외선→idx1). 본선 43역 +
    성수지선(244~246, 250) + 신정지선(247~249, 251) 포함. 까치산(251)은 2026-09-11 갱신에서
    처음 제공됐다(그 전까지 유일한 결손역). 성수지선은 본선과 극성이 반대라
    `line_direction.dart` 에 전용 분기가 있다(자세히는 커밋 `75b9e03`).
  - **9호선 (901~938)**: 38역 완행(`t`) + 급행 정차 16역(`tE`).
    급행 정차역: 902(김포공항) 905(마곡나루) 907(가양) 910(염창) 913(당산) 915(여의도)
    917(노량진) 920(동작) 923(고속터미널) 925(신논현) 927(선정릉) 929(봉은사)
    930(종합운동장) 933(석촌) 936(올림픽공원) 938(중앙보훈병원)
  - 방향 매핑: API `INOUT_TAG` 1=상행→`t` index0, 2=하행→index1. 전 노선에서 API 하행의 물리방향이
    앱 `isDownBetween`(하행)과 일치(1호선 남행=ID증가, 4호선 오이도=`_isLine4Down`, 9호선 개화=규칙반전 등).
  - **키잉 주의**: `t`/`tE` 키는 **앱 역ID**(stations.json id). 1~8호선은 API `FR_CODE`와 앱 역ID가
    다르므로(예: 종로3가 FR 130 vs 앱 131) 역명+노선으로 매칭 후 앱 역ID로 키잉한다.
    역명 표기차(예: 총신대입구(이수)→4호선 "총신대입구"/7호선 "이수")는 괄호제거/괄호내용 폴백으로 흡수.
  - 데이터 출처: 서울 열린데이터광장 `SearchSTNTimeTableByIDService` (OA-101),
    역코드는 `SearchInfoBySubwayNameService`. `.env`의 `SEOUL_GENERAL_API_KEY` 사용.
  - `we`는 WEEK_TAG=3(일요일/공휴일) 데이터. **토요일(WEEK_TAG=2)은 미반영** — 컴팩트 스키마가
    주말 1종(`we`)만 지원하는 한계.
  - 재생성: `dart run tool/build_metro_timetable.dart` (기본 1~8) / `--lines=9` 등으로 노선 지정.
- **비(非)서울교통공사 노선 12개**: 공공데이터포털 `getTrainSch`로 수집.
  - 대상: 신분당(SB, 16역)·경춘(33, tE24)·공항철도(14)·수인분당(63, tE51)·신림(11)·
    에버라인(14)·인천2(24)·서해(12)·의정부(14)·우이신설(13)·GTX-A(9)·김포골드(10). 전부 누락 0.
  - **김포골드**의 `lineNm` 은 개통 당시 명칭인 `"김포도시철도"` 다 — `"김포골드라인"` 으로 조회하면
    `totalCount=0` 이 돌아온다.
  - **행 제외 규칙 2가지** (`_collectLine`):
    - **당역종착** — `arvlStnNm` 이 조회역이면 버린다. getTrainSch 는 진짜 종점에서는 `trainDptreTm`
      을 `null` 로 주지만 **구간운행 회차역에서는 종착 열차에도 출발시각을 채워 넣어**, 그 방향으로
      가지 않는 "유령 출발"이 생긴다. 실측: 김포골드 구래 158편·신분당 정자 4편·수인분당 죽전 2편에서
      발생. 공항철도 검암·수인분당 왕십리/고색·서해 대곡/일산·경춘 상봉/평내호평은 API 가 이미
      `null` 처리해 무영향.
    - **비영업편성** — `_excludedTrainnoPrefixes` 의 trainno 접두사를 버린다. 현재 김포골드 `7xxx`
      1건뿐(7001/7002, 평일 04:40:00 양 종점 동시 출발, 주말 없음, 다음 출발까지 50분 공백,
      korailinfo·공식 안내 첫차는 양방향 05:30). 영업편성 2xxx/3xxx 와 번대가 분리돼 판별 가능.
    - 제외 건수는 노선별로 실행 로그에 출력된다(침묵 절단 방지).
  - **경춘**(C01~C24)과 **경강**(GG01~GG12)은 별개 노선으로 각각 `경춘선`·`경강선` 을 조회한다.
    2026-07-30 까지 경강선이 `'경춘'` 에 접혀 있어 한 lineId 로 두 노선명을 조회했다.
  - **급행 tE**: 경춘·수인분당은 `etrnYn=Y`를 tE로 분리 (`express_skip_edges.json`에 경춘·수인분당 존재).
    단 **주말 tE는 없음(`we.tE` 빔)** — getTrainSch가 주말 열차를 전부 `etrnYn=N`으로 제공(급행 플래그 미부여).
    데이터 소스 특성이며 tool 버그 아님.
    ⚠ **2026-08-13 정정**: 여기 "주말 급행 라우팅은 배차간격으로 graceful 폴백(오답·크래시 없음)"으로
    적혀 있었으나 **오답이었다.** `DaySchedule.periods` 는 완행 배차간격이라, 폴백이 "급행이 완행
    간격으로 온다"는 없는 열차를 만들었다(수인분당 주말 하행은 `pD` 가 05:00~23:36 를 덮어 하루 종일
    "9분마다 급행"). 이제 `findNextDeparture` 가 **급행 조회의 배차간격 폴백을 금지**(`express` 면 null)
    하고, 결과 화면이 그 요일에 시간표가 없는 모드를 탭에서 내린다.
    게이트가 정상 급행을 막지 않는 근거: `express_skip_edges.json` 의 급행 정차역(1호선 35·9호선 16·
    경춘 15·수인분당 36) 전부가 평일 `tE` 보유, 주말 결손은 경춘 15·수인분당 36 전역과 1·9호선 0.
    회귀 가드: `test/domain/usecases/express_no_headway_fallback_test.dart`.
    ⚠ 이 두 노선은 API가 **급행 통과역에도 `etrnYn=Y` 시각을 채워** 주므로 `tE`가 통과역에도 존재한다.
    그 값은 실제 정차 시각이 아니라 보간값이다. 다만 통과역에는 `{base}E` 가상 노드가 생기지 않아
    (`express_skip_edges.json`이 실제 정차역만 담는다) `findNextDeparture(express: true)`가 그 항목을
    조회할 경로가 없다 — 무해하지만 `tE` 자체를 정차 패턴의 근거로 쓰면 안 된다.
    정차 패턴의 유일 소스는 `tool/manual_express_stops.json`이다.
  - **방향 반전 4노선(공항철도·의정부·우이신설·김포골드)**: getTrainSch 하행 라벨이 앱 `isDownBetween`(상행)에
    해당하므로 뒤집어 저장(하행→idx0, 상행→idx1). 공항철도는 앱이 하행=서울역 방면(ID감소)으로 반전,
    의정부·우이신설·김포골드는 앱 일반규칙(ID증가=하행)이 getTrainSch 하행과 반대 방향. 나머지 8개는 정합(하행→idx1).
    검증: 공항철도 서울역(A01) 상행154/하행0, 인천공항2터미널(A14) 상행0/하행102.

  - 역명 표기차(예: 앱 `전대·에버랜드` → API `전대.에버랜드`)는 가운뎃점(·)/마침표(.) 정규화 폴백으로 흡수.

## 노선 대표값 (`f`/`l`/`p`/`pD`) — 앵커역 규칙

역별 시간표(`t`/`tE`)와 **출처가 다른 별개 계층**이다. `tool/extract_schedules.dart` 가
노선마다 **역 하나(앵커역)** 의 getTrainSch 행에서 첫차·막차·배차간격을 계산한다.

**앵커역은 반드시 "양방향 전구간 운행역"으로 고른다.** 회차역을 쓰면 그 방향 열차
대부분이 당역종착이라 API 가 `trainDptreTm=null` 을 주고, 살아남은 소수 편성이 노선
전체 대표값이 된다. 2026-08-13 에 두 노선을 정정했다:

| 노선 | 구 앵커(회차역) | 결손 | 신 앵커 |
|---|---|---|---|
| 수인분당 | 왕십리 | 상행 168행 중 159편 당역종착 → 9편 | **서울숲** |
| 경춘 | 상봉 | 상행 56행 중 42편 당역종착 → 14편 | **망우** |

정정 전 값과 정정 후 값:

| 노선·요일·방향 | 정정 전 `f` ~ `l` | 정정 후 |
|---|---|---|
| 수인분당 평일 상행 | 07:32 ~ 18:51 (배차 band 1개) | 05:51 ~ 00:18 (8개) |
| 수인분당 주말 상행 | 11:02 ~ 16:59 (1개) | 05:51 ~ 00:24 (8개) |
| 경춘 평일 상행 | 06:23 ~ 23:25 (2개, 06~10시만) | 05:34 ~ 00:04 (15개) |
| 경춘 주말 상행 | 06:51 ~ 23:22 (1개, 10~11시만) | 06:12 ~ 00:05 (14개) |

- 정정은 **JSON 직접 패치**로 했다(도구 실행 금지 — 위 재생성 명령 주의사항 참고).
  값은 새 앵커의 `t` 데이터에 `_analyzeStationTimes` 로직을 그대로 적용해 계산했다.
  두 노선은 `t` 와 `f/l/p` 가 **같은 출처(getTrainSch)** 라 이 계산이 도구 실행과
  동일한 결과를 낸다(구 앵커로 재현해 f/l/p 완전 일치 확인).
  ⚠ **1~9호선은 이 방법을 쓸 수 없다** — `t` 는 서울 열린데이터광장, `f/l/p` 는
  getTrainSch 라 출처가 달라 값이 재현되지 않는다.
- **사용자 노출 영향은 없었다.** `f`/`l`/`p` 소비처는 ① `_findNextByHeadway`(완행
  폴백 — 전 역이 `t` 를 보유해 도달 불가, 결손은 종착역의 진행 불가 방향뿐),
  ② `_nextStationDeparture` 의 `firstTrainMinutes`(전날 자정 넘김 판단 — 결과 동일),
  ③ `headway_estimator`(그래프 환승 대기) 셋이다. ③의 평시 배차는 정정 전후
  수인분당 8분→8분, 경춘 21.5분→21.6분으로 사실상 불변이라 경로 선정도 안 바뀐다.
  고친 이유는 `f`/`l` 이 "노선 첫차·막차"라는 자명한 이름을 가져, 이를 화면에 쓰는
  기능이 새로 생기면 즉시 오답이 되기 때문이다.
- 회귀 가드: `test/data/line_schedule_anchor_sanity_test.dart`. `f`/`l` 값이 아니라
  **배차 band 커버리지**를 잰다 — 자정 넘김 인코딩이 노선마다 달라(GTX-A 첫차가 실제로
  `00:06`, 경의중앙은 심야를 0~1439 로 저장) `f`/`l` 직접 비교는 거짓 실패가 난다.
  실측 분리: 정상 최소 1020분 vs 결손 4건 60·240·357·679분 → 임계 900분.
- **김포골드 `f`/`l` 은 여전히 어긋나 있다**(평일 `l=23:30` vs 실측 막차 24:58).
  앵커 문제가 아니라 이 노선이 `_getEstimatedSchedule` 하드코딩 추정치를 쓰기 때문이다.
  배차 커버리지는 1020분으로 정상 범위라 위 가드에 걸리지 않는다.

## 방향 결정 로직 (`direction_resolver.dart`)

- `RouteSegment`의 역 ID 순서로 방향 판별
- 일반 노선: ID 증가 = 하행(index 1), ID 감소 = 상행(index 0)
- 2호선 순환: 첫 두 역 ID 비교 + 순환 경계(201↔243) 처리
- 2호선 성수지선(244·245·246·250 관여 간선): 본선과 **반대 극성** — ID 증가 = 하행(신설동 방향).
  `lib/core/utils/line_direction.dart` 의 `_isLine2DownBetween` 전용 분기. 신정지선(247~249)은
  본선 공식과 극성이 같아 분기 불필요.

## 출발시각 계산 우선순위

1. 실시간 도착정보 API (가장 정확, 방향 필터 적용)
2. 역별 시간표 (이진탐색으로 다음 출발시각 반환, `t` 키 데이터)
3. 배차간격 기반 시간표 추정 (방향별, 역별 시간표 없는 노선)
4. 현재 시각 폴백 (운행 시간 외이거나 데이터 없음)

## 핵심 함수

- `findNextDeparture()` — `lib/domain/usecases/find_next_departure.dart`: 역별 시간표(이진탐색) 또는 배차간격으로 다음 출발 시각 계산 (`isDown`, `stationId`, `express` 파라미터). `express=true`면 급행 시간표(`tE`/`expressStationDepartures`)만 조회.
- `computeDepartureTime()` — `lib/features/route_search/utils/departure_time_calculator.dart`: 실시간 + 시간표 통합 계산 (방향 자동 결정, `stationId` 전달)
- `computeSegmentDepartures()` — 환승역에서도 방향별 시간표 기반 출발시각 계산 (`stationId` 전달)
- `isDownDirection()` — `lib/features/route_search/utils/direction_resolver.dart`: RouteSegment에서 하행/외선 여부 결정
